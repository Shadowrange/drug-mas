## 0. ЧТО В ВИДЕО И ЧТО ИЗ ЭТОГО ПРАВДА

Автор (@azizbuildss) забрал 4 приза на одном хакатоне. Механика — три правила:

| # | Правило в видео | Что реально решает |
|---|---|---|
| 1 | **Split the folders** | У каждого своя зона файлов. «Two agents never» трогают одно и то же → нет конфликтов слияния |

**Что здесь честно, а что монтаж.** [Уверен] Работает ядро: фиксированный префикс с именем агента, явное перечисление файлов, конкретика вместо «пофикси вёрстку», хеш коммита в ответе. [Предполагаю] Полностью автономная переписка агент→агент требует, чтобы у каждого в команде был свой агент, подписанный на упоминания GitHub. Поэтому у вас человек переносит сообщение в своего агента. **Ценность не в автономности, а в формате** — он заставляет писать проверяемые сообщения.

## 1. ЧТО БЕРЁМ, А ЧТО НЕТ

У вас 40 часов и один тяжёлый путь интеграции (Vina), а не десять параллельных фич. Настройка сетапа не должна съесть окно Tools Layer.

**Берём — 20 минут, окупается сразу:**
- владение папками (правило 1) — защищает от главного убийцы хакатонных команд, конфликта слияния в 3 часа ночи;
- один закреплённый issue как доска (правило 2);
- жёсткий формат сообщений (правило 3);
- `AGENTS.md` в корне репозитория — чтобы агент каждого участника знал границы.

**Не берём:**
- автономную переписку агентов через GitHub-вебхуки — настраивать дольше, чем выигрыш;
- ревью пулл-реквестов агентами с блокирующими статусами — у вас не будет времени на циклы ревью;
- отдельные ветки на фичу. При такой длительности — **одна ветка `main`, прямые пуши в свою папку**. PR заводим только на `schemas.py` и `verifier.py`, потому что их ломать нельзя.

## 2. ПРАВИЛО 1 — ВЛАДЕНИЕ ПАПКАМИ

Каждый файл имеет ровно одного владельца. Чужие файлы не трогает ни человек, ни его агент. Нужна правка в чужом — пишешь на доску, владелец делает сам.

| Владелец | Файлы | Не трогает никогда |
|---|---|---|
| **Р-A** (химия и инструменты) | `src/tools/chem.py`, `src/tools/admet.py`, `src/tools/qsar.py`, `src/tools/docking.py`, `tests/test_tools.py` | `src/agents/*`, `app.py` |
| **Р-B** (агенты и контракты) | `src/schemas.py`, `src/cache.py`, `src/verifier.py`, `src/tools/databases.py`, `src/tools/generate.py`, `src/agents/*`, `src/graph.py` | `app.py`, `src/tools/docking.py` |
| **Р-C** (фронт и демо) | `app.py`, `examples/`, всё по визуализации | `src/` целиком |
| **Р-D** (защита) | `README.md`, `docs/*`, презентация | `src/`, `app.py` |

### Два исключения, из-за которых обычно всё и ломается
1. **`src/schemas.py` — заморожен с 20:20 среды.** Это контракт между всеми слоями. Менять только Р-B и только после сообщения на доску. Каждая правка здесь ломает работу троих.
2. **`requirements.txt`** — дописывать можно всем, но **только добавлять строки**, никогда не переписывать файл целиком и не пинить чужие версии.

### Правило конфликта
Если `git pull` дал конфликт в чужом файле — **не разрешаешь его сам**. Откатываешь своё изменение, пишешь владельцу на доску. Разрешение конфликтов вслепую в последнюю ночь стоило победы большему числу команд, чем любой технический риск.

## 3. ПРАВИЛО 2 — ОДНА ДОСКА

Создать issue №1 в репозитории, озаглавить `📌 BOARD`, закрепить (Pin issue). Телеграм-чат доской не является: там сообщения тонут, а issue открыт у всех на втором мониторе.

**Постим туда ровно четыре типа сообщений. Ничего больше — ни обсуждений, ни мемов.**

### Тип 1 — взял в работу (обязательно перед началом блока)
```
[claim] Р-A / блок T1
Файлы: src/tools/chem.py, tests/test_tools.py
Делаю: дескрипторы, Lipinski, QED, SA Score, PAINS, 3D-конформер.
Возвращает list[Value] с provenance=COMPUTED.
Не трогаю: schemas.py, agents/*
ETA: 23:00
```

### Тип 2 — готово
```
[done] Р-A / блок T1 (коммит a3f91c2)
Работает: все 6 функций, тесты зелёные на иматинибе и аспирине.
Не работает: SA Score требует sascorer из RDKit Contrib — путь захардкожен, см. chem.py:14
Дальше разблокировано: T6, A2
```

### Тип 3 — заблокирован (пишем сразу, не через час)
```
[blocked] Р-A / блок D1
Проблема: Meeko не конвертирует рецептор в PDBQT, ошибка <точный текст>
Пробовал: <что именно>
Нужно: решение по R1 до 01:00
```

### Тип 4 — решение (пишет тот, кто решил; задним числом не меняется)
```
[decision] 23:40 — CReM не докачался, переходим на STONED-SELFIES.
Следствие: generate.py меняет сигнатуру, Р-B в курсе.
Откат невозможен после 10:00 четверга.
```

**Правило доски:** нет `[claim]` — значит, работа не начата, и любой может её забрать. Это единственный способ в три часа ночи понять, кто чем занят, не будя человека.

## 4. ПРАВИЛО 3 — ФОРМАТ СООБЩЕНИЙ

Работает и между людьми, и когда вы скармливаете сообщение своему агенту. Жёсткая структура нужна потому, что агент на расплывчатую фразу «почини докинг» начинает чинить всё подряд и ломает соседние файлы.

### Шаблон запроса на правку
```
[<Имя> / <агент>] @<владелец файла> — <файл>:<строка>
Симптом: <что именно наблюдается, с числами или текстом ошибки>
Причина: <если известна, иначе «не установлена»>
Предлагаемая правка: <конкретно>
Что НЕ трогать: <файлы вне зоны>
```

Пример под ваш проект:
```
[Кирилл / Argon] @shdrng — src/verifier.py:41
Симптом: кандидаты с provenance=PREDICTED проходят порог ΔG,
хотя ΔG не считался — в поле None, сравнение None < -7 падает в TypeError.
Причина: нет проверки на None до сравнения порогов.
Предлагаемая правка: если value is None → ветка «данных нет»,
не «порог не пройден». Это разные исходы для Сценария 3.
Что НЕ трогать: schemas.py, agents/*
```

### Шаблон ответа
```
[<Имя> / <агент>] @<автор запроса> — исправлено, коммит <хеш>
Что сделал: <одна строка>
Что проверил: <как убедился>
Перепроверь: <что именно>
```

### Три запрета
1. **Без хеша коммита «исправлено» не существует.** Фраза «я поправил» без хеша в этом проекте ничего не значит.
2. **Никаких «вроде работает».** Либо «проверил на иматинибе, 5 из 5 кандидатов прошли», либо «не проверял».
3. **Агент не чинит то, о чём его не просили.** Если агент тронул файл вне зоны владения — откат, независимо от того, стало лучше или нет.

## 5. ФАЙЛ `AGENTS.md` В КОРЕНЬ РЕПОЗИТОРИЯ

Это то, что читает агент каждого участника перед работой. Claude Code читает `CLAUDE.md`, поэтому делаем копию под обоими именами. Положить в корень `drug-mas/` прямо сейчас.

```markdown
# AGENTS.md — правила для всех ИИ-агентов в этом репозитории

## Контекст
Хакатон, 40 часов, защита 13.11. Прототип мультиагентной системы для
дизайна лекарственных молекул. Главное требование заказчика:
система обязана различать реальные расчёты, ML-предсказания и гипотезы.
Вымышленные числа недопустимы — это критерий оценки, а не пожелание.

## Жёсткие запреты
1. НИКОГДА не возвращай числовое значение без заполненного поля
   `provenance` и непустого `source`. Если значение неоткуда взять —
   верни None и отдельно укажи, какого расчёта не хватило.
2. НИКОГДА не придумывай SMILES, ΔG, IC50, ID из баз данных.
   Любое такое значение приходит из вызова инструмента или не приходит вообще.
3. НИКОГДА не редактируй файлы вне зоны владения текущего участника
   (таблица в TEAM-AGENT-RULES.md §2).
4. НИКОГДА не меняй src/schemas.py. Он заморожен. Нужна правка —
   остановись и скажи об этом человеку.
5. НИКОГДА не добавляй зависимость в requirements.txt без явной просьбы.
   Новый пакет — это риск сломать окружение троим.

## Обязательно
- Перед правкой назови файлы, которые тронешь, и дождись подтверждения.
- Все внешние вызовы — только через декоратор из src/cache.py.
  Прямые запросы к сети в обход кэша ломают офлайн-демо на защите.
- Каждая функция инструмента возвращает list[Value] (см. schemas.py).
- Пиши код так, чтобы он работал при OFFLINE=1 из кэша.
- Если задача требует тронуть больше трёх файлов — остановись
  и предложи разбить её.

## Стиль
- Python 3.11+, type hints обязательны, Pydantic v2 для всех границ.
- Без try/except, молча проглатывающих ошибку. На хакатоне тихий
  except — это полчаса поиска причины в три часа ночи.
- Комментарии только там, где неочевидно «почему», а не «что».

## Если не уверен
Скажи «не уверен» и назови, чего не хватает. Правдоподобная
догадка здесь дороже признания незнания: она уедет в демо
и всплывёт на вопросе жюри.
```

## 7. ЧЕГО НЕ ДЕЛАТЬ

**Не настраивайте процесс вместо работы.** Соблазн потратить вечер среды на красивую автоматизацию агентов вместо `tools/chem.py` — реальный и убивает команды чаще, чем технические риски. Двадцать минут из §6 — потолок. Всё, что сверху, вы доделаете после хакатона, если захочется.

**Не ставьте агентам задачи размером в модуль без схем на руках.** Пока `schemas.py` не написан, любой сгенерированный код придётся переписывать. Порядок из `PLAN-case1-sintez.md` §6 не декоративный.

**Не доверяйте агенту проверку provenance.** Это главная мысль обоих файлов. Проверка живёт в Pydantic-схеме и в `verifier.py`, а не в промпте и не в `AGENTS.md`. Запреты в §5 — это страховка, а не механизм.
